# 2026-10-25

## 更新界面两个 Qt 坑：叉号关不掉 / 进度窗不能最小化
- 用户反馈：①「本地已有安装包」那个 QMessageBox **点叉没反应**；②下载进度窗**没有最小化按钮**。
- **根因 1（很重要，通用）**：`QMessageBox` 在**没有任何 RejectRole 按钮时，标题栏叉号和 Esc 都失效**。
  实测三组：只有 Accept → 能关；Accept + Action（我们原来的写法）→ `close()` 完全无效，只能靠
  `done()` 兜底；Accept + Action + Reject → 能关。所以「不想放取消按钮、让用户点叉」这条路在 Qt 上根本不通。
- 修法：`_ask_cached` 改**自己排按钮**（QDialog + QVBoxLayout + QHBoxLayout + 3 个 QPushButton）。
  顺带按 role 重排的坑也没了 —— QMessageBox 在 Windows 上 RejectRole 永远紧跟 AcceptRole，
  三按钮必是 [立即安装][稍后][重新下载]（试过 Yes/No/Destructive role 组合，结论一样）。
  现在顺序是 [立即安装][重新下载][稍后]，叉号 / Esc / 「稍后」三条退路都返回 `''`。
  对话框 `setMinimumWidth(460)` + `setMaximumWidth(600)`：长路径自动换行又不会把窗口撑爆。
- **根因 2**：QProgressDialog 默认 windowFlags 里没有 `WindowMinimizeButtonHint`。
  但**只补最小化 hint 会多出一个灰掉的禁用「最大化」方块**（Windows 看到「有最小化、没最大化」就这么画）；
  一起给 `WindowMaximizeButtonHint` 后三个按钮才都是正常状态（已验证最小化/还原都正常）。
- 顺带把进度窗从 `Qt.WindowModal` 改成 **`Qt.NonModal` + parent=None**：
  模态时最小化自己之后父窗口仍被阻塞，点了没反应，比不能最小化更像卡死；非模态后可以最小化去干别的，
  也能继续用主界面。parent=None 是为了「下载期间关掉设置窗口不中断下载」（有父对象会被带走）。
  代价是 `_ok`/`_fail` 里拿到的 window 可能已经销毁 → 新增 `_alive()` 探活（碰 C++ 对象捕获 RuntimeError）。
- 新增模块级 `_update_dialog`：重复触发检查更新时把已有进度窗 `showNormal()+raise_()`，不再开第二个；
  关窗后 `_shut()` 里清引用。
- 测试：新增 `tests/__update_dialog_smoke.py`（24 项）——叉号/Esc/稍后/立即安装/重新下载五条出口、
  按钮顺序与默认按钮随 verified 变化、非模态、最小化 hint、最小化+还原、重复触发复用窗口、关窗停线程。
  真实 Windows 平台抓整窗截图（屏幕截图按 frameGeometry 裁剪，`grab()` 抓不到标题栏）确认外观。

## 顺手修：本地包文件名里的版本号与目标版本不符时不认
- 截图里「发现新版本 2.8.1」却认出了 `F.HamLog.2.7.setup.exe`（线上下载地址的文件名还是旧的）。
  `verified='name'` 只凭同名，点「立即安装」就是**装回旧版（降级）**，比重新下载严重得多。
- `find_installer()` 在最后一档（无元数据、仅同名）加一道核对：`_version_matches_name(path, version)`
  用正则从文件名抠版本号（`2.7` / `2.8.1`），与目标版本互相「不比对方新」才认；文件名不带版本号时放过
  （无从判断，仍交给界面提示未校验）。
- 测试补 J4–J6（cache smoke 29 → 32 项）。注意 `_same_or_older` 的双向比较就等价于版本相等，
  不用另写比较函数。

## 改回：判「同一个包」只看 exe 名称，不再比版本号（推翻上一节的 J4–J6）
- 上一节那道「文件名版本 vs 目标版本」核对是**净负担**：命名规则并不统一，`F HamLog 2.9 setup.exe`
  配版本 `2.9.0` 时，`_same_or_older` 双向比出来的结果是「不等」（`2.9` 补齐成 `2.9.0` 只在一个方向成立），
  已经下好的包被判成「不是这个包」→ 每次点下载都白重下几十 MB。
- 新增 `check_update.installer_name(path_or_url)`：只取文件名，小写，把空格/点/下划线/连字符都当分隔符
  （URL 里的 `%20` 也先 unquote）。`find_installer()` 的候选按它比对；**`version` 参数只为兼容保留、不参与判断**；
  元数据里也只比 url + size（大小不同 = 被截断或被换过）。真正要防的「装回旧版」由下载地址本身兜住 ——
  我们要装的本来就是这个地址指着的文件。`_version_matches_name()` 整个删掉。
- 测试 J4–J6 重写：版本参数不影响判断、名字归一化（大小写/分隔符/URL 编码）、名字不同就是另一个包。

## 下载相关窗口一律不能最大化（用户两次点名要求）
- 上一节「补 `WindowMaximizeButtonHint` 消除灰方块」的做法被推翻：用户明确要求**不能最大化**。
- 真机探针（`QT_QPA_PLATFORM=windows` + `GetWindowLongW(GWL_STYLE)`）看到：只删最大化 hint 时
  `WS_MAXIMIZEBOX` 确实没了（按钮变禁用、双击标题栏无效），但 `WS_THICKFRAME` 还在 →
  拖到屏幕上沿被 Aero Snap 拉满，`ShowWindow(hwnd, SW_MAXIMIZE)` 也能放大成 1536×841。
- 定稿 `_no_maximize(win)`：`WindowMaximizeButtonHint=False` + `MSWindowsFixedSizeDialogHint=True`
  （后者让 Qt 去掉 `WS_THICKFRAME`），再 `changeEvent` 里 `WindowStateChange && isMaximized() → showNormal()`。
  探针复验：两个窗口 `MAX=False MIN=(进度窗 True/提示窗 False) THICK=False`，`SW_MAXIMIZE` 后尺寸不变、`isMaximized()` 仍是 False。
- 落到两个窗口：`_UpdateProgressDialog(QProgressDialog)`（下载进度窗）、`_NoMaximizeDialog(QDialog)`
  （`_ask_cached` 的「本地已有安装包」提示框，之前是裸 QDialog，同样可被拖大）。
- 测试：dialog smoke 24 → 26 项（B4b 无最大化 hint、A10b 提示框不可最大化）。
