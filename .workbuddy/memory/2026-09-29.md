## 修复 preview.yml 提交检测 bug（@scene#15 日常开发）
- **根因**：`检查是否有新提交` 步骤用 `gh run list --limit=1` 取「上一次运行」，但 `gh run list`
  会把**正在运行的当前 run**（createdAt≈现在）也列进去，于是 `$since`≈现在 →
  `git rev-list --since≈现在` 永远计到 0 个提交 → 除首次运行外永远走「复用旧产物」分支，
  从不重新打包。现象就是"明明有提交却没重新打包"。
- **修复**：取上一次运行时**跳过当前 run（`github.run_id`）**，`--limit=10` 取前一条非自身的
  createdAt 作为 `$since`；查不到历史（首次）仍视为打包。除自身外无历史 → `$since` 为空 → 正常打包。

## 追加：真正的第二根因 = `$since` 时区丢失（仍"以为没新提交"）
- "跳过自身"只解决"取哪条 run"，**没解决取出来的时间串**。实测（用户仍报无提交）：
  - `gh run list` 的 `createdAt` 是 **UTC ISO 串**（如 `2026-09-28T12:00:53Z`）。
  - 旧代码 `$since = [string]$r.createdAt`（或 `$dt.ToString("MM/dd/yyyy HH:mm:ss")`）→ PowerShell 转成
    **无时区的本地时间串** `09/28/2026 20:00:53`（+8 已应用，但丢了 `Z`）。
  - git 对无时区串**按运行机器本地时区**解释；runner 是 UTC → 把 UTC20:00 当起点 → **凭空 +8h**，
    把窗口内提交（`c964105`/`8d15321`，UTC12:02~15:25）全漏掉 → count=0。
  - **本机(+8)自测"看起来对"**：本机 TZ 也是 +8，与转换后的本地串自洽 → 所以"本地怎么试都对、CI 永远错"。
  - 实测对照（origin/develop）：旧串 `09/28/2026 20:00:53` 在 TZ=UTC 数出 2、TZ=+8 数出 6；
    带 Z 的 `2026-09-28T12:00:53Z` 两处都数出 6。
- **修复**：显式输出带 `Z` 的 UTC ISO 串再喂给 git：
  `[datetime]::Parse(raw, InvariantCulture, AdjustToUniversal -bor AssumeUniversal).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")`。
- **踩坑：`gh run list` 的时间一律是 UTC**，凡喂给 git `--since` 必须显式带时区（Z），别用默认 ToString。
- **另一坑**：`git rev-list --count --since=...` **必须带 `<commit>...`**（如 `origin/develop`），
  漏了会打印 usage 退出；PowerShell 里引号要用单引号包整串（bash 才用双引号）。
- **状态**：时区修复已改在 `develop` 工作区（未提交/未推）。**待同步到 main**（定时任务实际分支）。
