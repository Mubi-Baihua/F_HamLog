## 调整：active 下载新增进度条

  结束报 100。active 与分类回退下载均走该逻辑。

  - 窗口布局新增 `QProgressBar`（随主 VLayout 放置，平时 `setVisible(False)`）；补 `QProgressBar`
    导入。
  - `refresh_tle`：开始下载时显示进度条并置 0；`on_progress_pct` 据 pct 切换确定/忙碌模式
    （pct<0 → `setRange(0,0)` 忙碌；否则 `setRange(0,100)`+`setValue`）；`on_fetched`/
    `on_warning`/`on_error` 均在结束时隐藏进度条。`progress`(文本) 仍写入 `status` 标签。
- 验证：py_compile 两个文件通过；分块下载单测覆盖「有 Content-Length→0/中间%/100」与
  「无 Content-Length→-1/100」；大文件(50KB)实测 6 个进度点；`satellite_window` 模块导入
  正常且 `TleFetchWorker` 含 `progress_pct` 信号。

## 新增：下载星历时可“取消下载”

- 用户要求：在下载星历的进度条右侧，添加取消下载的功能。
- `satellite_pred.py`：
  - 新增异常 `class TleFetchCanceled(Exception)`（用户取消，非错误）。
  - `fetch_amateur_tle` 新增可选参数 `cancel`（callable，返回 True 表示已取消）；
    `download` 在内部分块读取循环里每读一块就检查一次，命中即抛 `TleFetchCanceled`。
    active 与分类回退两处 `download` 调用都传入 `cancel=cancel`。
  - 关键修正：active 的 `except Exception` 与分类循环的内层 `except Exception` 都会**吞掉**取消异常，
    导致误判为“下载失败”。已在两处对 `TleFetchCanceled` 单独 `raise`，使其直接冒泡出函数。
- `satellite_window.py`：
  - `TleFetchWorker` 新增 `canceled = Signal()` 与 `self.cancel_requested = False`；
    `run` 传入 `cancel=lambda: self.cancel_requested`，并 `except sp.TleFetchCanceled: self.canceled.emit(); return`。
  - 进度条区改为 `QHBoxLayout`（进度条 + 「取消下载」按钮 `cancel_dl_btn`），按钮平时隐藏。
  - `cancel_download` 在 `refresh_tle` **外部**定义并只连接一次（动态读 `win._tle_worker`，避免每次刷新
    累加连接导致引用旧 worker 的泄漏）；点击置 `cancel_requested=True` 并变「取消中…」。
  - `on_fetched`/`on_warning`/`on_error`/`on_canceled` 四态均隐藏并复位 `cancel_dl_btn`；
    新增 `on_canceled`：隐藏进度条、复位按钮、恢复「刷新TLE」、状态显示「已取消星历下载」，不弹错误框。
- 验证：py_compile 通过；单测覆盖「不取消正常返回(27点进度)」「active 路径中途取消」「分类回退路径中途取消」
  三场景均正确抛出/冒泡 `TleFetchCanceled`；模块导入正常且 `TleFetchCanceled` 信号存在。
  注：`satellite_window.main()` 在本沙箱 offscreen 下窗口构建即硬崩溃（环境限制），完整 UI 端到端未跑。
