## 查明：插件（.fhlpypack）对 .fhla 的支持边界（只读调研，未改代码）
- 插件接口 `project.py: run_pack`（约 3905–3934）**与格式解耦**：写 `input.fhl`（`json.dump(file)`，
  即纯 `list[dict]` 记录数组，明文）+ 读 `output.fhl` 覆盖 `file` + `table_update()`。
- 因此 `.fhla` 项目**能跑插件**：`_fhla['meta']`（属性块 / 自定义字段定义）始终留在主程序内存，
  插件看不见也改不了；保存仍走 `write_fhla_file`，属性块原样带回，且因 `snap != _fhla['open_snap']`
  被记为一次编辑（刷新 last_editor / last_edit_time / last_version）。
- 边界：插件拿不到字段定义（显示名/顺序/必填/主页显示）与 last_editor 等；文件名与 README 仍只提 `.fhl`；
  **插件不得按 `.fhla` 结构（`{"xml":…,"project":…}`）写 output**，否则 `file` 变 dict，`table_update()` 会崩。
- 若要真正支持：在 pack 目录额外给 `input.xml`（属性块）或改双段 `{records, meta}`，
  需按 pack xml 的 `available fhl version` 做旧插件兼容。

## check_update.py 403 修复（Cloudflare 拦 Python-urllib UA）
- 症状：`urllib.error.HTTPError: HTTP Error 403: Forbidden`，指向 `mubi-baihua.pages.dev/f_hamlog_check_update.txt`。
- 根因：**UA 没发出去**。原代码先 `urlopen()` 再 `r.add_header(...)`，`add_header` 加在**响应对象**上，对已发出的请求无效；实际 UA = `Python-urllib/3.13`，Cloudflare 对该 UA 直接 403（`curl -A Python-urllib/3.13` 复现 403，Mozilla UA 200）。
- 修法：`urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"})` 后 `urlopen(req)`，`with` 收尾。
- 验证：`PYTHONPATH=src .venv/Scripts/python.exe src/f_hamlog/check_update.py` → `2.7.0 https://github.com/.../F.HamLog.2.7.setup.exe`。
- 同类已 OK：`satellite_pred.py` 的 `_download_url` / `probe_tle_source` 早就带 `F-HamLog/2.0 satellite prediction` UA，无需改。
- 追加：加了容错重试（`MAX_RETRIES=5`，退避 0.5/1/2/4/5s，单次 `TIMEOUT=10`）。
  用户手写版是**递归 `main(retry+1)`**，有两个致命问题：① `if retry == 10` 写在递归**之后**，永远轮不到 → 无限递归；
  ② 裸 `except:` 连 `RecursionError` 一起吞，栈爆后继续递归刷屏。已改成 `while` 循环，保留 `main(retry=0)` 签名。
  `PERMANENT_CODES=(400,401,404,410,451)` 直接放弃；403/408/429/5xx/网络异常类才重试。
  测试 `tests/__check_update_retry_smoke.py`（4 例：网络全失败=6 次请求+退避序列 / 404=1 次 / 503=6 次 / 抖动第 3 次成功=3 次）。
  真实 403 复验：重试 2 次后收敛返回 None，不再崩溃。
