## 查明：插件（.fhlpypack）对 .fhla 的支持边界（只读调研，未改代码）
- 插件接口 `project.py: run_pack`（约 3905–3934）**与格式解耦**：写 `input.fhl`（`json.dump(file)`，
  即纯 `list[dict]` 记录数组，明文）+ 读 `output.fhl` 覆盖 `file` + `table_update()`。
- 因此 `.fhla` 项目**能跑插件**：`_fhla['meta']`（属性块 / 自定义字段定义）始终留在主程序内存，
  插件看不见也改不了；保存仍走 `write_fhla_file`，属性块原样带回，且因 `snap != _fhla['open_snap']`
  被记为一次编辑（刷新 last_editor / last_edit_time / last_version）。
- 边界：插件拿不到字段定义（显示名/顺序/必填/主页显示）与 last_editor 等；文件名与 README 仍只提 `.fhl`；
  **插件不得按 `.fhla` 结构（`{"xml":…,"project":…}`）写 output**，否则 `file` 变 dict，`table_update()` 会崩。
- 若要真正支持：在 pack 目录额外给 `input.xml`（属性块）或改双段 `{records, meta}`，
  需按 pack xml 的 `available fhl version` 做旧插件兼容。

## 实现：插件双输入 + 双输出（.fhla 优先），README 中英同步
- `project.py: run_pack` 重写：
  - 输入同时写 `input.fhl`（纯记录，老接口）+ `input.fhla`（`{"xml": ordered_meta(meta), "project": records}`，
    **手写 JSON 而不是 write_fhla_file**：后者会 touch/mark_opened，改掉 last_version；`encrypted` 强制 false）。
  - 输出：`output.fhla` 存在则优先（记录 + 属性块整体替换，**不合并**，`_fhla['meta']` 换掉并置 `dirty=True`），
    否则读 `output.fhl`（只换记录）。
  - `output.fhla` 用 `json.loads` 手动解析（不走 `read_fhla_file`），因为要区分「project 缺失/非列表」与
    「空项目」——否则插件写错结构会被 `fhla_project` 静默当空项目、清空整份日志。
  - `output.fhla` 坏掉/缺 project **不回退** `output.fhl`（避免静默丢属性改动）；`new_recs` 必须是
    `list[dict]`，否则报「不是记录列表」并保持原样。
  - 运行前先删残留 `output.*`（插件崩溃会留下上一轮结果）；结束后四个文件全清。
  - 空项目时 `file` 可能是 None → 写 `[]`（老代码会写出 `null`）。
  - 加密项目读回明文 `output.fhla` 后把 `new_meta['encrypted']` 改回真实 `bool(key)`。
