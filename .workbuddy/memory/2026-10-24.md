## 查明：插件（.fhlpypack）对 .fhla 的支持边界（只读调研，未改代码）
- 插件接口 `project.py: run_pack`（约 3905–3934）**与格式解耦**：写 `input.fhl`（`json.dump(file)`，
  即纯 `list[dict]` 记录数组，明文）+ 读 `output.fhl` 覆盖 `file` + `table_update()`。
- 因此 `.fhla` 项目**能跑插件**：`_fhla['meta']`（属性块 / 自定义字段定义）始终留在主程序内存，

  **插件不得按 `.fhla` 结构（`{"xml":…,"project":…}`）写 output**，否则 `file` 变 dict，`table_update()` 会崩。
- 若要真正支持：在 pack 目录额外给 `input.xml`（属性块）或改双段 `{records, meta}`，
  需按 pack xml 的 `available fhl version` 做旧插件兼容。

## check_update.py 403 修复（Cloudflare 拦 Python-urllib UA）
- 症状：`urllib.error.HTTPError: HTTP Error 403: Forbidden`，指向 `mubi-baihua.pages.dev/f_hamlog_check_update.txt`。
- 根因：**UA 没发出去**。原代码先 `urlopen()` 再 `r.add_header(...)`，`add_header` 加在**响应对象**上，对已发出的请求无效；实际 UA = `Python-urllib/3.13`，Cloudflare 对该 UA 直接 403（`curl -A Python-urllib/3.13` 复现 403，Mozilla UA 200）。
- 修法：`urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"})` 后 `urlopen(req)`，`with` 收尾。
- 验证：`PYTHONPATH=src .venv/Scripts/python.exe src/f_hamlog/check_update.py` → `2.7.0 https://github.com/.../F.HamLog.2.7.setup.exe`。
- 同类已 OK：`satellite_pred.py` 的 `_download_url` / `probe_tle_source` 早就带 `F-HamLog/2.0 satellite prediction` UA，无需改。
- 追加：加了容错重试（`MAX_RETRIES=5`，退避 0.5/1/2/4/5s，单次 `TIMEOUT=10`）。
  用户手写版是**递归 `main(retry+1)`**，有两个致命问题：① `if retry == 10` 写在递归**之后**，永远轮不到 → 无限递归；
  ② 裸 `except:` 连 `RecursionError` 一起吞，栈爆后继续递归刷屏。已改成 `while` 循环，保留 `main(retry=0)` 签名。
  `PERMANENT_CODES=(400,401,404,410,451)` 直接放弃；403/408/429/5xx/网络异常类才重试。
  测试 `tests/__check_update_retry_smoke.py`（4 例：网络全失败=6 次请求+退避序列 / 404=1 次 / 503=6 次 / 抖动第 3 次成功=3 次）。
  真实 403 复验：重试 2 次后收敛返回 None，不再崩溃。

## 下载窗：点叉关不掉 / 宽度 / 剩余时间 / 加速
- **点叉关不掉的根因**：`QProgressDialog.setValue()` 内部会 `ensureDialog() → show()`，
  所以 `close()` 之后只要还有一帧进度信号进来，窗口就自己弹回来。修法：`state['closed']` 标记 +
  `_shut()`（**先 `reset()` 再 `hide()`**，顺序反了 reset 又把它 show 出来），`_progress` 见标记直接返回。
  实测：`close()` 后 `setValue(50)` → visible 又变 True，正是这个现象。
- 宽度 600 → **540**：文案改成 `已下载 / 总大小 · 速度 · 剩余 xx:xx`（去掉「正在下载更新…」前缀，
  标题栏已有「下载更新」）。实测中文 ≤526、英文 ≤538，540 不抖；QProgressDialog **只会变宽不会变窄**
  （调到 658 后换回短文案仍 658），所以最小宽度就是实际宽度。
- 剩余时间：`format_eta()` → `00:42` / `01:02:03`（语言无关，'剩余'/'ETA' 走词表）。
- 加速三板斧（GitHub CDN 限的是**单连接**）：
  1. `WORKERS 8 → 16`、`MAX_WORKERS 16 → 32`、`PART_MIN_BYTES 1MB → 512KB`（12MB 文件实测 16 段真并发 16）；
  2. 分段连接超时 `TIMEOUT → PART_TIMEOUT=15`：卡住的连接 15 秒断开重连；
  3. 镜像择优 `choose_source()`：直连 + 4 个前缀式镜像（ghfast.top / gh-proxy.com / ghproxy.net /
     ghproxy.cc）并行跑 2 秒测速窗口，**镜像要快 1.3 倍才换**；换之前 `probe` 确认支持 Range
     （有的代理返回 200 整包 → 只能单线程，反而更慢）。
- 镜像安全：走镜像后 `_spot_check()` 从官方地址取头/中/尾各 64KB 比对；不一致就删掉重走直连。
  版本文件支持第三段 sha256（`parse_text` 返回三元组），有摘要就整包校验、校验失败直接删文件。
- 测试：新增 `tests/__update_source_smoke.py`（16 项，本地限速服务模拟快慢镜像、篡改内容、不支持 Range 的代理）；

## 下载窗：剩余时间不跳变 + 宽度 540 → 480
- **剩余时间跳变的根因有两层**：
  1. 原来用「短窗瞬时速度」算 `(total-done)/speed`，速度抖一倍，剩余时间就跳几十秒；
  2. 更隐蔽的是 `_Meter.add()` **在锁外调 callback**：多个分段线程同时 add 时，信号按发射顺序排队，
     后算出来的**更小 done 可能先到界面**（实测 8.25 MB → 8.19 MB 倒退），ETA 每帧都被判成「回退」→ 重置。
- 修法：
  - `_Meter.add()` 把 `self.callback(...)` **移进锁内**（实测槽在 MainThread 执行，是排队信号）；
  - 新增 `check_update.EtaEstimator`：速度只认**累计平均**（`(done-done0)/dt`），显示值**只降不升**，
    要上调必须先超出死区 `max(0.3, min(2.0, eta*20%))`，再每帧最多挪 `max(0.5, eta*5%)`；`done` 回退
    当帧不重算（**不重设基准**，否则每回退一次都要重新预热，ETA 一直不显示）；`warmup=1 s` 内返回 None。
  - 死区随剩余时间缩放，否则末尾几秒会一直卡在 `00:00`。
- 宽度：文案 `{}/{} MB · 速度 · 剩余 {}`（数字与斜杠间不留空格），中文需 408 px、英文 420 px，
  `setMinimumWidth(480)`（标签可用 458）。QProgressDialog 只增不减，480 就是实际宽度。
- 测试：新增 `tests/__update_eta_smoke.py`（26 项，可控时钟）：预热、匀速准确性、快慢交替抖动下
  **最大跳变 0.73 s（朴素算法 28.5 s）**、持续掉速会缓慢上调（最大 1.48 s）、done 回退不消失不跳、
  70 MB/1 MB/s 真实尺度中途误差 <1 s、尾声不早归零。`__update_flow_smoke.py` 改 20 项：
  服务端放慢到每 32 KB 停 120 ms（否则 1 秒内下完，预热期还没过），断言宽度 470~560、
  剩余时间至少 3 个采样且**相邻跳变 ≤3 秒**。
