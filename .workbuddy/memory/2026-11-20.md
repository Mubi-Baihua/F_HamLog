### ② 加密日志（`加密此项目` / `不再加密此项目`）
- **根因**：两条菜单都走 `save(message=False)`（静默自动保存），它在「本会话已写过同样内容」时直接 return
  → 文件根本没被重写：加密后仍是明文、解密后仍是密文，看起来就是「加密不可用」；`aouto_save` 关掉时更是一次都不写。
- 修法：新增 `_write_project_now()`（= `_write_project_file(save_path)` + `_bk_clear/_bk_snapshot`），无脑整份写盘；
  写失败回滚 key（`_set_key(None/input_key)`）并提示 `加密失败 / 写入文件失败：{}`；改 key 时置 `_fhla['dirty']=True` 记一次编辑。
- `save_path` 为空（恢复的项目）→ 提示「请先保存此项目（Ctrl+S），再加密。」
- `osave()` 现在**真的把 save_path 换到新文件**（原来只写文件、不换路径 → 另存为之后 Ctrl+S 还写旧文件，
  也让「先保存再加密」永远拿不到路径）；与 `_save_recovered_as` 行为对齐，并刷新 `window._local_title`。
- 新增 `fhl_rw.get_new_key_dialog(parent)`：`_ask_key_pair`（同窗口两行密码 + 一个显示/隐藏）→ 空/不一致就
  `QMessageBox.warning` 后**重新弹框**，直到一致或取消；`get_user_key_dialog`（读取时用）保持单次输入不变。
- 新文案已进 `i18n_zh_en.py`（设置加密密钥 / 密钥： / 再输入一次密钥： / 确认密钥 / 两条重输提示 /
  请先保存此项目… / 写入加密文件失败：{} / 写入文件失败：{}）。

## .adi 的「项目属性」不再套 .fhl 话术（23:3x）
- 现象：打开 .adi 按「项目属性」，弹的是三行「不支持的格式：当前项目不是 .fhla 文件 / …请另存为
  带属性的 .fhla 项目文件后再查看」——只有中间一行换成 ADI 的说明，看着就是 .fhl 那套提示。
- 改法（`project.py`）：`show_project_props()` 按真实格式四路分流，新增 `describe_adi(path, count)` +
  `ADI_FIXED_VALUES` + `_human_size()`：
  * `.fhla` → 属性块（行为不变，`describe_meta`）；
  * `.adi` → 文件：格式（ADIF 日志交换格式）/ 记录条数 / 文件大小 / 修改时间 / 加密：无 / 项目属性：无，
    末行才给一句「需要项目属性时，可用『另存为』保存为 .fhla 项目」；
  * 未保存 → 「当前项目还没有保存到磁盘 / 保存后（Ctrl+S）才能查看」（原来会误报 .fhl 文案）；
  * `.fhl` → 保持原「不支持的格式」提示。
  翻译照旧逐行：属性名全查词表，值只翻 `ADI_FIXED_VALUES` 里的固定文案（文件名/数字/时间原样）。
- `i18n_zh_en.py`：新增 格式/记录条数/文件大小/修改时间/加密 + ADI 两句固定值 + 两条「未保存」文案；

- 测试：新增 `tests/__adi_props_smoke.py`（34 项全过，含「ADI 弹窗里不出现 .fhl」、英文界面、.fhl/.fhla 回归）；
