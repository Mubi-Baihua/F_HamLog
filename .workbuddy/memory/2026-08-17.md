# 2026-08-17

## 修复 satellite_map_window.py
- **Bug**：`MarkerManageDialog.__init__` 用到 `QAbstractItemView` 但未 import，触发 `NameError`。已在顶部 QtWidgets import 中加入 `QAbstractItemView`。
- **平滑晨昏线阴影边缘**：`_draw_night_shade` 由 6°×6° 矩形网格改为沿晨昏线（1° 间隔）+ 极边闭合的 `QPainterPath` 多边形抗锯齿填充，再沿界线多遍半透明描边（7/4.5/2px，alpha 20/28/38）羽化。
- **修正晨昏线方向（关键 bug，用户报了 3 次「阴影反了/阴影区使光照区」）**：
  - 第一版用黄经 `lam%360` 当地理经度 → 东西翻转约 180°。
  - 第二版按 Meeus 重写（真黄经→视黄经→赤纬+赤经→GMST→地理经度），但 **subsolar 经度公式写反**：写成 `sun_lon = gmst - ra_deg`，正确应为 `sun_lon = ra_deg - gmst`（由 H = GMST + 经度(东正) - RA = 0 推得）。错误符号使晨昏线偏移约 69~127°，北半球中纬度（如北京 22:00 本地）被误判为白昼。
  - 修正后验证（同步渲染取 3×3 邻域中位数避免单像素海岸线/网格线伪影）：北京/悉尼=夜、伦敦/开罗/纽约=昼，方向全部正确。纽约像素偶显暗是因其恰在美国东海岸海岸线上（与阴影无关）。
- **标记点管理增加网格输入** → **改为梅登黑格坐标导入**（用户澄清：不是自由文本，而是从梅登黑格网格坐标导入，页面与 TQSL/转发器类似）：
  - 移除上版的 `QPlainTextEdit` 文本区、`QSplitter`、「文本→表格/表格→文本」按钮及 `_parse_text/_rows_to_text/_import_from_text/_export_to_text`，`satellite_window` 的 `DictEditorDialog` 保持表格 Expanding 纵向填满（与标记点管理风格一致）。
  - `MarkerManageDialog` 现：表格（名称/纬度/经度/颜色，Expanding + `layout.addWidget(self.table, 1)` 纵向填满）+ 按钮（添加 / 删除选中 / **从梅登黑格导入** / 保存 / 关闭）。
  - 新增 `MaidenheadImportDialog`：粘贴每行一个梅登黑格坐标（4/6/8 位，大小写不限），支持 `名称=网格` 或 `名称 网格`（网格取末段）；经 `sp.maidenhead_to_latlon` 解码后追加为标记点行。
  - 解码后加 **地球范围校验**（`-90≤lat≤90` 且 `-180≤lon≤180`），超出则归入错误列表并用 `QMessageBox.warning` 提示跳过（捕捉共享解码器对越界字母如 `ZZ99` 不报错的问题）。
- **三处表格纵向填满窗口**：`MarkerManageDialog` 表格 Expanding + stretch 1；`satellite_window.DictEditorDialog`（TQSL 映射与转发器设置共用）表格 `setSizePolicy(Expanding)` 且 `lay.addWidget(self.table, 1)`。两者均 Expanding 纵向填充。
- 顺带删除死代码 `_is_night`、`_solar_elevation`；新增 `import sys`（satellite_map_window）与 `QSizePolicy`（satellite_window）。
