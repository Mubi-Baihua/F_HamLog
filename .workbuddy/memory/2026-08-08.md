# 2026-08-08

## 卫星地图「聚焦卫星」交互完善（satellite_map_window / satellite_window / mutual_window）
- 用户反馈两条：①"多数情况无法聚焦卫星"；②"无法通过点击过境列表聚焦卫星"。
- 分层根因：
  1. 地图自身不能鼠标点击聚焦、下拉框选单颗也不设 focus（已修：画布点击 + 下拉框选星即聚焦）。
  2. 来源窗口（卫星过境 / 通联预测）表格点击 `_on_table_sel` 在地图**未打开**（或已关）时直接 `return`，
     不会自动开图聚焦——这是"点击列表无法聚焦"的主因（只有按"卫星地图"按钮才开图）。
- 本轮修复：satellite_window.py 与 mutual_window.py 的 `_on_table_sel` 改为——
  若 `win._map_window` 为 None 或不可见，则调用 `open_map()`（其内部读取当前选中行作为初始聚焦卫星），
  否则 `set_satellite(name)`。实现「点列表即聚焦」。
- 验证（offscreen 冒烟测试）：
  - 地图已开：selectRow → set_satellite 生效，focus 随选中行切换。
  - 地图未开：selectRow → 自动 open_map 且 focus=选中星名，entry.focus=True（整条加粗）。
- 现聚焦卫星有三种入口：① 来源列表点行（自动开图/聚焦）；② 地图"显示"下拉框选某颗；③ 地图画布点卫星。

## 聚焦仍然失效的二次根因（真正修复）
- 用户复测"点击过境列表还是没有聚焦"。前一轮改 `_on_table_sel` 自动开图/聚焦**逻辑是对的**，但实测发现
  `set_satellite` 一进函数就 `return`——因为名字不匹配：**`parse_tle_text` 把 TLE 原始名称行（尾随空格填充）
  当字典键，而 `satrec.name`/表格 `r['name']` 是 strip 后版本**，导致 `name not in self._sats` 永远成立。
  前一次"手工注入单星"测试因名字恰好一致未暴露此问题。
- 修复：`satellite_pred.parse_tle_text` 两处 `name` 赋值加 `.strip()`（与 `twoline2rv` 内部 strip 一致）；
  并在 `satellite_map_window.set_satellite` 入口加 `name = name.strip()` 防御。
- 验证（真实 TLE 离屏）：点过境列表第 0 行→自动开图、`focus=该行星名`、`entry.focus=True`；切行焦点跟随；通联预测同样通过。
- 该修复同时消除了 TQSL 映射 / 转发器查找潜在的按名错位隐患（这些函数原本靠自身 `.strip()` 兜底）。

## 关图后再点列表无法重开 + 地图宽度异常
- 用户复测又报两个新问题：①点一次列表开图、关图后再点（同一行）无法重开；②地图界面宽度异常。
- 重开失效：根因 `itemSelectionChanged` 只在「选中行变化」时触发，关图后点已选中的同一行选择未变→不触发→`_on_table_sel` 不调用。
  修复：列表改挂 `cellClicked`（每次点击都发），`_on_table_sel` 接受可选参数；`satellite_window`/`mutual_window`
  均加 `cellClicked` 连接并跳过「记录」按钮列（过境列6 / 通联列7）。验证：关图后点同/异行均重开且焦点正确。
- 宽度异常：信息条 `QLabel` 默认不换行，`minimumSizeHint` 宽度=整段状态文字单行宽度(~1776)→把窗口最小宽顶到~1794，
  覆盖 `resize(960,600)`，窗口被撑到 1938 宽。修复：信息条 `setWordWrap(True)` + `setMinimumWidth(0)`。
  验证：宽度 1938→1012（过境）/1192（通联，控件更多）。两窗口均修。

## 通联预测与卫星过境地图宽度不一致
- 用户复测：两处打开的地图宽度不同（通联预测偏宽约 180px）。
- 根因：地图控制条里的「对方最低仰角」组（`_el_b_label`/`_el_b_spin`）仅在通联预测（有 station_b）时
  `setVisible(True)`，卫星过境时隐藏。`setVisible(False)` 的控件不计入布局最小宽度，于是两种来源的
  `resize(960,600)` 被各自不同的内容最小宽度覆盖，最终宽度不一致。
- 修复：`MapWindow.__init__` 在构建控制条后，临时把该组设为可见、量一次
  `centralWidget().minimumSizeHint().width()` 作为**统一最小宽度** `setMinimumWidth(_uniform_min_w)`，
  再恢复该组真实可见性。这样无论哪种来源，窗口最小宽度都被约束为「含对方最低仰角」的宽度，两者一致
  （卫星过境那组虽隐藏，但窗口不会因此变窄）。`set_stations` 运行时切换可见性不影响已定的最小宽度。
- 验证：真实 TLE 离屏，两处打开地图均 width=1192、minW=1192，宽度一致=True。

## 地图保持正确比例（2:1 等距圆柱投影）
- 用户反馈：窗口中的地图被拉伸，希望保持正确比例。
- 根因：`MapCanvas` 所有投影直接基于整个画布 `self.width()×self.height()`，而等距圆柱投影的世界
  本应是 2:1（经度 360° : 纬度 180°）。窗口任意拉伸时，地图被压扁或拉长。
- 修复：`MapCanvas` 新增 `_map_rect()`，在画布中居中放置一个固定 **2:1** 的「地图矩形」；
  所有经纬度→像素换算（`_xy`）、底图缓存（`_render_base`）、覆盖区（`_draw_footprint`）、
  图例（`_draw_legend`）均基于该矩形。画布其余区域填海洋色作为 letterbox 留边。
  - `_render_base` 缓存尺寸改为地图矩形尺寸；`paintEvent` 先填整画布海洋色，再把底图平移到
    矩形位置 `(rx, ry)`。
  - `_draw_footprint` 生成的覆盖区路径先平移 `(x0, y0)` 再绘制，确保其在地图矩形内。
- 验证：对超宽、超高、正方形、默认窗口四种比例，`_map_rect()` 宽高比均 = 2.0000，且 (0°E, 0°N)
  始终落在矩形中心；离屏截图显示地图比例正确、无拉伸，留边为海洋色。

## 地图铺满窗口 + 保持比例正常
- 用户反馈：希望地图铺满窗口、窗口尺寸不变、同时地图尺寸正常（不拉伸）。
- 根因：上一轮让 `_map_rect()` 居中固定 2:1 并加 letterbox，导致窗口四周有海洋色留边，地图未填满。
  若直接铺满当前 1192×600 窗口，内部画布只有 1174×512（比例 2.293），横向会被拉伸约 15%，不正常。
- 修复：
  1. `MapCanvas._map_rect()` 改为返回整块画布 `(0, 0, W, H)`，实现地图铺满。
  2. `MapWindow` 新增 `showEvent()`：首次显示时按「画布宽度/2」反推所需窗口高度，并将窗口高度
     锁定为 2:1（实测 1192 宽 → 675 高，画布 1174×587 精确 2:1）。宽度保持 1192 不变，满足统一宽度。
- 验证：卫星过境 / 通联预测两个来源打开的地图，窗口均为 1192×675、画布 1174×587（aspect=2.0000）、
  fills=True（地图铺满），最小高度锁定为 675。
