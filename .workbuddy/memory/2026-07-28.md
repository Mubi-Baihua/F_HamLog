# 2026-07-28 工作日志

## 修复：nuitka 打包后无法读取星历数据（卫星过境功能）

**现象**：用 nuitka `--standalone` 打包后，打开“卫星过境预测”时无法读取星历/星历（TLE）数据。

**根因（两处，互补）**：
1. **打包命令缺资源文件**（确定性失败，双击也炸）：`--include-package=skyfield` 只打包了 Python 代码，
   没有打包 `skyfield/data/*.npz`（iers.npz/delta_t.npz/nutation.npz/constellations.npz）。
   `load.timescale(builtin=True)` → `load_bundled_npy('iers.npz')` → `get_data('skyfield','data/iers.npz')`
   找不到文件 → 整个卫星运算崩溃。与 CWD 无关，双击 exe 也会失败。
2. **TLE 缓存/设置用 CWD 相对路径**（从非 exe 目录启动时失败）：`satellite_pred`/`satellite_window`/
   `satellite_auto_update` 里 `file/amateur.tle`、`file/m_xml.txt` 用的是相对路径，代码此前只给
   sat_radio_dict.txt / tqsl_dict.txt 修了 `_DATA_DIR`，TLE 漏了。

**修复**：
- `打包.txt`：在 `--include-package=skyfield` 后加 `--include-package-data=skyfield`（关键）。
- `satellite_pred.py`：新增 `_app_base_dir()` / `app_path(rel)`，优先返回“确实含 file/ 子目录”的目录
  （exe 目录优先于 `__file__` 目录），所有数据路径（TLE 缓存、设置、dict 表）经 `app_path` 解析为绝对路径；
  导出 `TLE_CACHE = app_path('file/amateur.tle')`。
- `satellite_window.py` / `satellite_auto_update.py`：`SETTINGS_PATH`、`TLE_CACHE` 改为 `sp.app_path(...)`。

**验证**：py_compile 通过；`load.timescale(builtin=True)` 在 venv 正常（iers.npz 在）；模块自测
`python satellite_pred.py` 出 4 次过境；模拟“打包后从无关 CWD 启动”场景，`app_path('file/amateur.tle')`
正确解析到 exe 旁的 `file/amateur.tle`。

**注意（遗留/未改）**：`main.py`/`project.py`/`set.py`/`input_adi.py` 等核心模块仍用 CWD 相对
`open('file/...')` 读 `m_xml.txt`/`main.fhl`，同样存在“从非 exe 目录启动即失败”的隐患，本次未动
（超出本 bug 范围、改动面大）。建议后续统一抽一个全局 app 路径 helper。
