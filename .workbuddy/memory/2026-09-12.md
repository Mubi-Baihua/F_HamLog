## 新增：未保存内容自动备份与恢复（@scene#15 日常开发）

实现 F HamLog 的崩溃/异常关闭恢复机制，新增模块 `backup.py`：

- 备份文件：`file/project_backup.fhl`（沿用项目加密 key）与 `file/batch_backup.fh`（始终明文）。
- 语义：备份文件非空=有可恢复内容；空文件(0字节)=无需恢复。空列表写入即置空。
- 打开项目/批量记录时：把当前(已保存)内容写入备份作基线；正常保存(`save`/`osave`/`esave`/`append_to_project`/`save_all`)后清空备份并更新快照。
- 周期定时器(1.5s)：存在未保存更改(当前 `file`/表格 与快照不一致)时写入备份，覆盖崩溃场景。
- 关闭守卫 `install_close_guard`：无未保存→直接关并清备份；有未保存→弹「保存/不保存/取消」。保存=落盘+清备份；不保存=保留含未保存内容的备份(供下次恢复)；取消=保持打开。
- `main.py` 启动(`QTimer.singleShot(0)`)读取两个备份，非空则弹「恢复/忽略」；恢复则打开对应窗口并回填(`batch_project.main(preset_records=...)`)，随后清空备份避免重复提示。
- 验证：venv(PySide6-Essentials) offscreen 冒烟通过——backup.py 单测、关闭守卫三分支、批量窗口基线写入/干净关闭清空/恢复回填全部 PASS。注意 `project.py` 主窗口 offscreen 硬崩溃（已知环境限制），故项目窗口 GUI 路径未能 headless 验证，逻辑与批量窗口同源。

## 新增：卫星选择对话框「未搜索时已选卫星置顶」（satellite_window.py）
- 需求：`SatelliteSelectDialog` 在**未搜索**（搜索框为空）时，始终把已勾选的卫星排到列表顶部。
- 实现（`satellite_window.py`）：
  1. `_reorder_pin_selected()`：按“已选在前(保持各自原相对顺序) + 未选在后”物理重排 `QListWidget` 的 item，并同步 `self._row_names`（供 `_filter` 按行隐藏用）。顺序未变则直接 return（避免闪烁）。
  2. `_filter()` 末尾：`if not self._keys: self._reorder_pin_selected()`——仅未搜索时置顶；搜索中不重排（只显示匹配项）。

  4. 重排守卫 `self._reordering` 防 `itemChanged` 递归。
- **性能要点**：取出全部 item 时用尾部 `takeItem(count-1)`（每次 O(1)）而不是 `takeItem(0)`（每次 O(N)），再追加式 `insertItem` 插回，整体 O(N)，避免数千颗卫星时 O(N²) 卡顿。item 对象始终被 `self.items` 引用不会被回收。

### 多人日志「未保存更改」判定优化（@scene#16）
**问题**：原判定 = 「当前内容 != 最近一次**本机写盘**的快照」。多人日志下 `_on_sync` 会整份替换 `file`（含**他人**改动）→ 每次同步都变脏，后果两条：① 1.5s 备份定时器把共享会话日志写进 `file/project_backup.fhl`，下次启动 main.py 误报「恢复未保存的内容」，恢复还可能覆盖本机项目；② 关闭窗口无端弹「未保存的更改」（明明内容早已在服务端）。

**新规则（双基线）**：`_bk_state = {'last': 已持久化基线, 'local': 最近一次写入本机文件的内容}`。
- `_bk_json()` 统一序列化；`_bk_snapshot()`：**`last` 总更新；仅当 `_rc() is None`（非多人日志）时才更新 `local`** —— 这一条让所有既有调用点（save/osave/_save_recovered_as/append_to_project/打开时）自动正确，无需改调用方。
- `_on_sync`：内容与服务端一致时也要 `_bk_snapshot()`（自愈，避免「本地编辑恰好等于服务端内容」永久卡在脏）；采纳服务端内容后 `_bk_snapshot()`（服务端=已保存）。
- `_bk_write(force=False)`：**多人日志下不写本机备份**（`force` 仅供关闭守卫「不保存」分支，确有未同步内容时仍留备份）；`_bk_tick()` 定时器在多人日志下直接 return。
- `_bk_on_remote_exit()`：退出会话时重算 —— `last = snap if snap == local else ''`（哨兵 '' = 恒脏）。挂在 `_detach_remote()`（含 `_close_lan`、关窗）与 `_on_disconnect()`（被动断开）两处。**语义：只有「内容相对最近一次写盘确有变化」才算未保存**，既不再无端提示，又保留「不保存会丢内容」的安全网。
- `_attach_remote`：进入会话时补一次 `_bk_snapshot()`（只动 `last`）。`recovered` 场景 `last/local` 都置 ''。
- `backup.install_close_guard` 新增可选 `texts()` 回调（title/text/save/discard/cancel）；`project.py` 传 `_bk_close_texts()` → 多人日志下文案为「未同步到服务端 / 有内容尚未同步到服务端，是否立即同步？/ 同步 / 不同步」，单人模式仍是「未保存的更改 / 保存 / 不保存」。
