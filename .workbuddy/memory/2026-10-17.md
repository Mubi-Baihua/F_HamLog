## 修复：预览版 Actions 在「校验打包产物」失败（main.dist 找不到）
- **症状**：Nuitka 打包成功，下一步抛 `未找到主程序：…\main.dist\F HamLog 2 Preview.exe`。
- **根因**：Nuitka 默认用**主模块文件名**给产出目录命名 → `--main=src/f_hamlog/__main__.py`
  产出 `__main__.dist` / `__main__.build`（CI 日志原话：`Successfully created …\__main__.dist`、
  `Keeping build directory '__main__.build'`）。`main.dist` 是入口还在仓库根 `main.py` 时的
  遗留假定，src 布局迁移后没人跟。连带后果：`actions/cache` 的 `main.build` 永远对不上 →
  缓存空转，每次 1090 个 C 文件全量重编（本次实测 41 分 39 秒）。
- **修法**：打包命令加 `--output-folder-name=main`（Nuitka 官方选项，4.1/4.3 都有；
  `OutputDirectories._getResultBaseName()` 用它同时决定 `.build` 与 `.dist` 基名），
  下游（`.iss` 的 `SourceDistDir=RepoRoot\main.dist`、兼容版 zip、`.gitignore`、缓存路径）
  全部原样不动。**不**改成 `__main__.dist` —— 那个名字会随入口文件名再变，坑还在原地。
- 顺手：`--include-module=remote_crypto` → `f_hamlog.remote_crypto`（`import remote_crypto`
  只存在于独立服务端目录；客户端全是 `from f_hamlog import remote_crypto`，旧值等于把 crypto
  编了两份，其中一份是死代码）。
- 校验步骤失败时列出实际存在的 `*.dist` 目录，下次再错一眼看到真名。
- 实证：本地最小包 `--main=tiny.py` + `--output-folder-name=main` → 生成 `main.dist`/`main.build`；
  同一命令去掉该选项 → `tiny.dist`（即 `__main__.py` 会是 `__main__.dist`），与 CI 现象一致。
- 解析校验：两份 yaml 过 `yaml.safe_load`；4 个改动步骤的 PS 脚本过 `[Parser]::ParseFile`
  （坑：无 BOM 的 UTF-8 在 Windows PowerShell 5.1 下会误报语法错，校验时写 BOM 或用 pwsh 7）。
- 注意：**定时**预览跑的是默认分支（main）上的 workflow 文件，只改 develop 不生效；
  `打包.txt` 已同步该选项（调试版用 `main-debug`，免得覆盖正式产物）。

  原因（读 `MainControl.py` L311-325 + `Importing.getPackageSearchPath` 得到）：
  `--include-module` 的解析发生在**编译主模块之前**，那时搜索路径只有「主模块所在目录 + sys.path」；
  `src` 要等 `__main__.py` 里那句 `sys.path.insert(0, src)` 被 Nuitka 记账后才生效，
  所以点分名 `f_hamlog.*` 在该阶段必然找不到。旧值 `remote_crypto` 能成立，纯粹因为它就躺在
  主模块目录 `src/f_hamlog` 里。
- 最终做法：**整行删掉**。实证 —— `--main=src/f_hamlog/__main__.py`（不带任何 include-module，
  并 nofollow 掉 PySide6/numpy/pandas/matplotlib/skyfield/cryptography/scipy）跑
  `--generate-c-only --show-modules`，日志有
  `Nuitka-Inclusion: Included compiled module 'f_hamlog.remote_crypto'`（连 main / project 一起），
  说明它是被 `project.py` 的 `from f_hamlog import remote_crypto` 自动跟随收录的，
  那行既是死代码又埋了坑。
- 两份 workflow 与 `打包.txt` 都加了「别再往这里加 --include-module」的注释，说明理由。
