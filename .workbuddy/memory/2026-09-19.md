### 关键坑：Windows 上「探测端口是否被占用」的正确写法
排查过程逐层否决了三种错误做法，最终结论（已写进代码注释与 MEMORY.md）：

1. **connect 探测不可用**：`settimeout()` 后 `connect_ex` 对**空闲**端口返回
   `WSAEWOULDBLOCK(10035)`，与占用无法区分（占用实测返回 0）。
2. **探测 socket 绝不能设 `SO_REUSEADDR`**：Windows 允许在已设置 `SO_REUSEADDR` 的情况下
   bind 到**同一地址已监听的端口**，导致探测恒判「空闲」。实测：
   holder 在 127.0.0.1 时，probe 127.0.0.1 + reuse=True → bind **成功**（漏判）；
   reuse=False → `FAIL(10048)`（正确）。
3. **Windows 绑定语义不对称，必须试探完全相同的地址**：
   - holder `127.0.0.1` → probe `127.0.0.1` FAIL / probe `0.0.0.0` **OK（漏判）**
   - holder `0.0.0.0`   → probe `0.0.0.0` FAIL / probe `127.0.0.1` **OK（漏判）**

   本项目服务端一律以 `0.0.0.0` 监听，故探测口径就是 `0.0.0.0`（`host` 为空/`::` 时归一为 `0.0.0.0`）。

最终实现（bind 探测、不设 SO_REUSEADDR、按同地址）：
```python
def _can_bind(host, port):        # True=可绑定(空闲)
    s = socket.socket(...)        # 注意：不要 setsockopt SO_REUSEADDR
    try: s.bind((host, int(port))); return True
    except OSError: return False
    finally: s.close()

def is_port_in_use(host, port):
    if not port: return False
    bind_host = host if host and host != '::' else '0.0.0.0'
    return not _can_bind(bind_host, port)
```

### 离屏测「主窗口 + 模态提示」的新坑（重要）
1. **`main()` 里 `win.show()` 后的同步模态框会阻塞主线程** —— 直接在模块顶层调 `main()`
   会让计时器根本没机会跑。必须 `QTimer.singleShot(80, lambda: sw.main(None))` 延迟触发，
   让计时器链先就位，再进入 main() 内部的模态循环。
2. **`QMessageBox` 标准按钮的 `text()` 带助记符**：实测是 `'&Yes'` / `'&No'`，
   按文本精确匹配 `== 'Yes'` **永远点不到**（表现为测试停在二次确认框上直到超时）。
   必须用 `w.button(QMessageBox.StandardButton.Yes)` 按 role 匹配。自定义 `addButton`
   的按钮（如「清除所有选择」）文本无 `&`，可以按文本匹配。
3. m_xml 里 `m_lat/m_lon` 为 0,0 时会先弹「设置观测站」引导框，抢在超限提示前面 ——
   实机测试前先把坐标写成非零值（如 39.9/116.4/50.0），测完还原。
